# Plain copy

Words are part of the design. Write for the person who sees them: a car buyer, a seller, a sales officer, a branch manager.

## Rules
- Name things the way the user does: "Sell your car", not "Vehicle disposal request". One name for one thing everywhere.
- A button says what will happen: "Send sell request", "Save draft", "Approve and list". The message after it uses the same words: "Sell request sent."
- Sentence case. Active voice: "The manager rejected your request." Short sentences, one idea each.
- An error says what went wrong and how to fix it, without apology or blame: "Enter the year." "This registration number is already used by another vehicle."
- An empty state gives the next step: "You have no requests yet. Send your first sell request."
- Write numbers the way people read them: Rs 5,400,000. 74,000 km. 14 March 2027.
- A notification says who did what to which car, in one line.

## Never
- Filler: please note that, we are pleased to, in order to, seamless, robust, powerful, cutting-edge, unlock, elevate, effortless, leverage, delve.
- Vague messages: Oops, Something went wrong, Invalid input, Success!, No data found, Unauthorized, Access denied.
- Slogans, exclamation marks, emoji, or a heading that only repeats the page name.
- A different word for the same action on different screens.

## Before and after
- "Oops! Something went wrong." becomes "We could not save the inspection. Check the fields marked in red."
- "Invalid input" becomes "Enter a valid phone number, for example 0300-1234567."
- "Submit" becomes "Send sell request".
- "Unauthorized" becomes "You need to log in first."
- "Access denied" becomes "This page is not for your account."
- "No data found" becomes "No cars match these filters. Try a higher price."

## Documents and commit messages
- A commit message is one line in the imperative that says what changed and why it matters ("Refuse arrival for an expired sell request"). Not "update stuff".
- A report or README says what the system does, who uses it and how to run it. Mark every guess as Assumption and every idea as Proposal.
