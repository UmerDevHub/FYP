# Slice S0: Setup

Status: not started
Size: 3 days (Estimate). Both people.
Read first: docs/progress.md, docs/architecture.md.

## Goal
Both laptops run the same empty project, and Claude follows our rules from the first session.

## Use cases
None. This slice builds no feature.

## What to set up
- Tools on both laptops: Node.js (a current LTS version, written in .nvmrc), Git, PostgreSQL (16 was used in the tested slice), an editor, and the Claude desktop app.
- A private GitHub repository. The folders of docs/architecture.md. npm workspaces: apps/*, packages/*.
- Files from the pack: CLAUDE.md, apps/api/CLAUDE.md, apps/web/CLAUDE.md, packages/shared/CLAUDE.md, .claude/settings.json, .claude/skills/, docs/.
- Prettier, ESLint and Vitest with a small rule set. Scripts in the root package.json with the names of CLAUDE.md (dev, dev:api, dev:web, test, lint, format, migrate, seed, demo:reset, job:expire).
- .gitignore (with .env and the uploads folder) and .env.example with fake values only.
- Two databases on each laptop: one for development and one for tests (the test database name ends in _test).
- A one-page README: install, run, test.

## Rules for this slice
- Do not write any feature code. The API may answer one test route and the web app may show one page that says "Vehicle 360".
- Use the same Node version on both laptops (a different version causes errors that look like code problems).
- No new library beyond: Express, Knex with pg, Zod, a password hashing library, a JWT library, helmet, a rate limiter, multer or a similar upload library, React, Vite, React Router, TanStack Query, React Hook Form, Tailwind, lucide-react icons, the @fontsource font packages, Vitest, Supertest, Playwright (from S9), ESLint, Prettier. Anything else: ask first (this list is a Proposal).

## Not in this slice
- Tables, migrations, seeds, login, screens, design tokens (S1).

## Done when (from a fresh clone, on both laptops)
1. npm install works.
2. npm run dev starts the API and the web app, and the page shows "Vehicle 360".
3. npm test runs and passes (one placeholder test is enough).
4. npm run lint and npm run format work.
5. A new Claude session in the project folder lists CLAUDE.md under its memory files, and answers "Which command runs the tests, and where do I put a new status name?" correctly (npm test, packages/shared/src/constants.js).
6. Both people committed once and pushed to the private repository.
