## Goal
The manager sees the stock of all branches with days in stock and ageing group. Accepted sell requests that nobody uses expire by themselves after 7 days.

## Use cases
UC-28 Monitor Inventory and Stock Ageing, UC-39 Run Scheduled Jobs (request expiry only).

## Requirements (word for word from the SRDS)
- FR-BM-06 Branch vehicle list. The system shall show the Branch Manager all vehicles of their
  branch in every status with filters. [Phase 1; UC-28]
- FR-IV-01 Real-time stock view. The system shall show a Branch Manager the vehicles of all
  three branches with status and availability, using current data. [Phase 1; UC-28]
- FR-IV-05 Stock ageing. The system shall show for every vehicle the number of days in stock
  and group vehicles in ageing ranges set in the system settings. [SRDS marks it Later; the
  plan moves it in; UC-28]
- FR-NT-04 Scheduled jobs. The system shall run scheduled jobs to expire sell requests,
  bookings and unconfirmed appointments and to send follow-up reminders. [Phase 1; UC-39]
- FR-BM-01 Sell request decision. The system shall let a Branch Manager accept or reject a
  Pending sell request of their branch. A rejection shall have a reason. An accepted request
  shall expire if the seller does not arrive in time. [Phase 1; UC-23, UC-39]
- NFR-MT-05 Values likely to change (expiry periods, slot length, ageing ranges, lead rules)
  shall be system settings and not written inside code.
- NFR-CR-01 A record shall never be in a status that is not allowed. Invalid transitions shall
  be refused by the server.
- A-03 Sell request statuses are Pending, Accepted, Rejected, Expired and Completed. An accepted request expires if the seller does not arrive within 7 days.

## Rules for this slice
- The stock list shows vehicles of all branches (read only, FR-AU-07 allows it for managers): status, branch, days in stock, ageing group. Filters: branch, status, make. A filter with no match gives an empty list and a clear message, not an error.
- Days in stock = today minus received_at. The ageing group is calculated, never stored. Proposal ranges: 0 to 30, 31 to 60, 61 to 90 and over 90 days, from LIMITS.AGEING_DAYS.
- Only managers may call the stock list. Sales staff and customers get 403. The stock list has no record endpoint and no edit.
- The job expireOverdue(now): find Accepted requests whose expires_at has passed, set them to Expired through changeStatus, write the history row, notify the customer in-app and by e-mail. It takes "now" as a parameter so tests can fix the time.
- The job runs from the hourly timer in scheduler.js, once at start-up, and by hand with npm run job:expire.
- Running the job twice changes nothing the second time and sends no second notification (FR-NT-04). Pending, Completed and not-yet-due requests stay as they are.
- The e-mail failing must not stop the job (NFR-RL-02): log it and carry on.

## Data
No new table. Index: vehicles (branch_id, status) where not deleted, and the expiry index from S3.

## API
GET /api/vehicles/stock?branchId=&status=&make=. No URL for the job.

## Screens
- Inventory (manager): a table of all branches: plate badge, car, branch, status badge, days in stock and the ageing group written in words ("31 to 60 days"). Filters above the table. A clear empty state.
- The Expired badge and a short message on My requests (customer).

## Not in this slice
Other scheduled jobs (booking expiry, follow-up reminders), transfers, dashboards, settings screens.

## Done when
1. The manager sees the stock of all three branches and the filters work.
2. A seeded request accepted 8 days ago becomes Expired when you run npm run job:expire, the customer is notified once, and running the job again changes nothing.
3. A car received 45 days ago shows 45 days and the group "31 to 60 days".

## Tests that must exist (AT-35 to AT-39, AT-40)
- Normal: stock list shows every branch; filters work; 45 days gives the group 31 to 60. The job expires an overdue Accepted request and the customer gets one notification.
- Refusals: sales staff and customers get 403. Running the job twice changes nothing. Arrival for an expired request is refused (AT-40). Use fixed dates; never wait for a real hour.

## Open points
