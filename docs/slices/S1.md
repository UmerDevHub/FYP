# Slice S1: Foundation

Status: not started
Size: 4 days (Estimate). Server: Umer. Screens: Habib (Proposal).
Read first: docs/progress.md, docs/architecture.md, docs/data-model.md, docs/design.md.

## Goal
Build only what every later slice needs: the database base, the shared package, the error handling, the UI kit and the app shell.

## Use cases
UC-34 Manage Branches: seed data only (three branches). No screen.

## Requirements (word for word from the SRDS)
- FR-AD-07 Seed accounts. Until the Admin screens are built, the system shall provide a seed
  script that creates the first Admin, the Branch Managers and the Sales Staff accounts.
  [Phase 1; UC-33]
- FR-AU-06 Role-based access control. The system shall check the role of the user on the
  server for every protected operation and shall refuse operations that the role is not
  allowed to perform. [Phase 1]
- NFR-MT-04 Database changes shall be made only through versioned migration files.
- NFR-SC-09 Passwords, API keys and tokens of external services shall be kept in environment
  settings and not in source code or in the repository.
- NFR-US-03 Buttons, status labels, messages and dialogs shall look and behave the same on all
  screens. Status shall be shown by text and not by colour alone.

## Server work
- app.js and server.js. Environment settings that stop the server at start-up with a clear message when one is missing.
- Database connection. A plain configuration for migrations and seeds. bigint parsed to a number once.
- ApiError, the one error handler (the shape of docs/architecture.md), and the request validator that puts clean values in req.valid.
- First migration: branches, users, refresh_tokens, password_resets, notifications, activity_logs. Enum types for roles.
- Seed: three branches and five demo accounts (admin, manager of branch 1, sales staff of branch 1, sales staff of branch 2, customer). One demo password, development only, written in the README.
- packages/shared: roles, statuses, LIMITS and the first schemas.
- Test set-up: runs migrations once, empties the tables before each test file, refuses to run unless the database name ends in _test, helper to make a user (the login helper is added in S2, when login exists).
- Endpoints: GET /api/health and GET /api/branches.

## Screen work
- Vite and React app, router, three layouts: public, customer, staff.
- Design tokens in index.css (docs/design.md). Fonts from npm.
- UI kit in components/ui.jsx: Button, Field, Select, Textarea, Badge, Card, Dialog, EmptyState, Spinner, Toast, PriceTag, PlateBadge.
- lib/api.js: one API client with one shared refresh promise. lib/format.js for price, date and mileage.
- A hidden kit page that shows every component in every state (default, hover, focus, disabled, busy, error).
- A header menu that changes by role (fixed values for now).

## Not in this slice
- Login, any business table, any business endpoint, any real screen.

## Done when
1. GET /api/health and GET /api/branches work and the second returns the three seeded branches.
2. npm run demo:reset empties the database, migrates and seeds, and can be run twice.
3. The app shell shows the three layouts.
4. The kit page shows every component, including disabled, error and busy states, at 360 px and at 1280 px.
5. npm test passes and refuses to run against a database that does not end in _test.

## Tests that must exist
- The error handler returns the shape { error: { message, details } } for a validation error, for an ApiError and for an unknown error (generic message, 500).
- The shared schemas accept the smallest and largest value and refuse one beyond each.
